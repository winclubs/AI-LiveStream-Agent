## 一、项目定位、愿景与核心痛点破局

### 1.1 专为电商无人值守带货而生

在电商直播领域，真人主播面临**“招聘成本高昂（月薪普遍破万）、通宵熬夜体力不支、状态起伏大、流失率高、话术容易违规”**等痛点。**AI-LiveStream-Agent** 旨在为中小商家、代运营品牌提供一台**“不知疲倦、话术标准、极具逼单压迫感且绝不违规”的 7×24 小时无人值守带货中枢**。

### 1.2 为什么不能用于“娱乐、才艺、情感”类直播？

本系统在产品哲学上坚决执行**“减负聚焦”**策略，拒绝做平庸的泛娱乐系统：
1. **即兴度与微表情壁垒**：娱乐主播依赖眼神流转、掩面大笑、撒娇卖萌、即兴接梗等超高自由度的面部微表情，以及站立起伏、舞蹈动作。目前的端侧数字人技术（固定切片循环 + 嘴周局部重绘）无法提供真人级即兴表演，生搬硬套到娱乐场景会呈现极度假面感，观众秒退；
2. **平台封号雷区**：各大短视频平台对“娱乐录播挂机”实行零容忍机审与人审，而对**“货架电商无人直播”**（信息清晰、真实答疑、合法合规带货）拥有完全不同的商业容忍度；
3. **商业变现确定性**：娱乐直播打赏不确定，无法支撑大模型 API 成本；带货直播直接沉淀 GMV 交易转化，投资回报率（ROI）高度可控。

### 1.3 核心技术杀手锏：“动静分离 / 批播结合”架构 (Batch-Stream Hybrid)

为打破“画质逼真度”与“实时低延迟交互”不可兼得的技术鸿沟，系统在架构上首创落地了**“动静分离 / 批播结合”**工程管线：

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                       【静】云端高精离线批处理 (占据直播 85% 时长)              │
│  确定性商品台词 (卖点/规格/逼单) ───► 云端 A100 + ByteDance LatentSync 官方扩散模型 │
│                                      │                                      │
│                                      ▼                                      │
│                          高精 1080P MP4 带货切片资产池 (真人级唇齿/发丝自然)   │
└──────────────────────────────────────┬──────────────────────────────────────┘
                                       │ 无缝智能编排轮播
                                       ▼
┌─────────────────────────────────────────────────────────────────────────────┐
│              【结合】混合切片缝合器 (HybridStitcher 状态机 + FrameBus 优先级发布总线)      │
│  同源底模坐标 ──► 4步 Smoothstep 跨帧平滑 ──► 切片音频对齐投递 + 每轮播微变速防查(±1.5%) │
│                                   ──► 语气过渡词 TTS 注入 ──► 动态不可觉高斯微扰    │
│                                       ▲                                     │
└───────────────────────────────────────┼─────────────────────────────────────┘
                                       │ 观众弹幕提问 / 现场插话 (barge-in 瞬时打断)
┌──────────────────────────────────────┴──────────────────────────────────────┐
│                       【动】本地轻量流式实时引擎 (占据直播 15% 时长)             │
│  弹幕电商意图提权 ──► LLM 针对性话术 ──► TTS 流式合成 ──► Wav2Lip-256 实时重绘        │
│                     (秒级针对性作答，解答完毕按 REWIND_SENTENCE 策略切回断点) │
└─────────────────────────────────────────────────────────────────────────────┘
```

1. **“静”（Batch 预渲染切片池 · 85% 主流程 · 端云统一收敛至 ByteDance LatentSync 官方扩散模型）**：
   - 商品主规格、痛点剖析、倒计时逼单话术是**确定性、重复播放**的；
   - **算力绝对统一**：无论在本地高性能显卡（RTX 3090/4080/4090，显存 ≥16GB）还是云端算力节点（A100 / RTX 4090），**全部统一运行官方 ByteDance LatentSync 扩散模型** 离线批处理渲染为高清切片，突破实时推流单帧 40ms 算力天花板，获得无可挑剔的真人级牙齿细节与自然质感；
2. **“动”（Stream 实时流式响应 · 15% 交互插入）**：
   - 当观众在直播间发弹幕询问“*主播，165高100斤穿什么码？*”时，系统瞬时打断切片播放；
   - 本地 **Wav2Lip-256 原生 ONNX 引擎**以低延迟前向推理实时生成答复，随后按 `REWIND_SENTENCE`（句首安全回退）策略智能接回切片断点，杜绝半句跳词。**单帧耗时随硬件与模型规格浮动，请以 `lipsync_preflight` 的实测推理延迟为准**（该接口按真实推理延迟判定本地可达帧率）；
3. **“结合”（跨帧平滑缝合与全维度防封检测）**：
   - 依托同一主播原片坐标（`coords.pkl`）及 **4步 Smoothstep 非线性 Alpha 融合**，切换过程无撕裂感、无卡顿；
   - 切片音频经过**纯 PCM 采样级对齐提取**，支持 50ms 平滑交叉淡入淡出（Crossfade）；
   - **音频防查双防线**：每轮切片循环自动刷新微变速时域拉伸（`uniform(0.985, 1.015)`），切片衔接处动态注入“好嘞/那么接下来”自然过渡语 TTS，打破机械循环；
   - 叠加底层**动态高斯微扰与光影律动**，使逐帧像素持续离散变化，降低平台录播静态指纹比对命中率。

### 1.4 传统六大行业死结破局对比表

| 行业传统痛点 | 平台处罚 / 转化恶果 | 本系统破局方案 |
| :--- | :--- | :--- |
| **单张死图动嘴** | 肢体完全僵硬，观众一眼识破假人，停留极短 | **真人实拍视频一键切片**，提取面部坐标（`coords.pkl`），发丝与呼吸起伏逼真保留 |
| **全视频死循环** | 播放循环交界处产生严重撕裂跳帧 | **数学镜像往返算法 (`mirror_index`)**，连续索引映射，消除首尾突变 |
| **口型迟钝错位** | 声音停了嘴还在动，音画严重漂移 | **PTS 单调时钟驱动** + `SharedPlaybackClock` 采样级 AV-Sync 动态对齐（EMA α=0.2 平滑，自适应丢帧/复帧节奏调节） |
| **无互动不会带货** | 机械念稿，无促销节奏，缺乏购买紧迫感 | **工业级 SKU 货盘 + 逼单状态机 + 优惠券倒计时** + 5 大带货动作手势联动 |
| **插不上话自说自话**| 现场连麦或突发情况无法打断 AI 发言 | **全双工 RMS 能量 VAD 开嗓检测** + `flush_talk` 瞬间闭嘴并清空队列（实际延迟受浏览器采集帧长与网络往返影响，以 `/metrics` 的 `live_agent_audio_first_frame_p95_ms` 等实测指标为准） |
| **电脑硬件门槛极高**| 动辄要求万元旗舰显卡，中小商家难以承受 | **动静分离 + 四级算力调度**：离线高精切片预渲染，本地轻量卡流畅互动；无显卡如实拦截告警，绝不静默降级假唇形 |
| **平台封禁“录播挂机”**| 画面长时间像素静态，被算法检测封禁 | **视觉动态防查（不可觉高斯微扰 + 光影律动）**，逐帧像素持续离散，降低平台静态比对命中率 |

## 二、开发语言与技术栈全景

本系统采用全异步、高可用、可插拔的工业级微核分层架构设计：

```mermaid
flowchart TD
    subgraph Client [前端与交互控制层]
        C1[Electron 桌面客户端 (内置绿色 Python 运行时)]
        C2[HTML5 + ES6 模块化暗黑控制台 (Emerald & Amber 极简美学)]
        C3[WebRTC / WHEP 毫秒级低延迟音画视窗]
    end

    subgraph CoreBackend [后端中枢 (Python 3.12+ / FastAPI)]
        B1[FastAPI + Uvicorn 异步 ASGI 引擎]
        B2[SQLite 3 WAL 模式 + SQLAlchemy 2.0 Async]
        B3[AES-256-GCM + Windows DPAPI 硬件级加密]
        B4[LLM 预算熔断器与 0-Token 节能冷场轮播引擎]
    end

    subgraph Brain [直播决策大脑与风控]
        A1[OpenAI 兼容端点矩阵 (DeepSeek / Qwen / Kimi / GLM / MiniMax / GPT / Gemini* / Claude*)]
        A2[BM25 + 稠密向量双路召回 RAG 知识库]
        A3[Aho-Corasick 毫秒级敏感词/广告法过滤引擎]
        A4[促单逼单决策状态机 & SKU 货盘引擎]
    end

    subgraph AvatarEngine [视听与数字人驱动层]
        D1[AvatarDriverFactory 注册中心]
        D2[本地 LiveTalking 驱动 (对接外部 LatentSync 服务)]
        D3[云端 GPU Sidecar 节点 (LAS3 协议 / Tesla T4 / A100)]
        D4[NativeNeural 原生 LatentSync ONNX 驱动 (进程内推理 · 禁假唇形回退)]
        D5[5 大动作切片状态机 (mirror_index 对称往返)]
    end

    subgraph AudioSpeech [全双工音频与拟人语音]
        S1[SenseVoice / Faster-Whisper 本地 ASR + RMS-VAD]
        S2[Edge-TTS / 阿里百炼 CosyVoice / ElevenLabs / MOSS-TTS]
        S3[拟人换气微停顿与助词注入引擎 (Humanizer)]
    end

    subgraph Distribution [多路媒体推流与分发]
        M1[OBS Virtual Camera 虚拟免驱摄像头 (直通直播伴侣)]
        M2[FFmpeg 管道 RTMP 全平台直播直推 (H.264 + AAC)]
        M3[MP4 带货短视频切片录制器]
    end

    Client <--> CoreBackend
    CoreBackend --> Brain
    CoreBackend --> AvatarEngine
    CoreBackend --> AudioSpeech
    AvatarEngine --> Distribution
```

## 六、完整功能矩阵与模块清单

### 1. 数字人资产制作工场 (Avatar Task Engine)
- **30秒~1分钟真人闭口短视频一键生成**：上传真人出镜视频（MP4/MOV，**全程自然闭口微合、不张嘴说话**），后台异步流水线自动处理：
  1. 视频解析与逐帧切片提取（`full_imgs/`），设置最大 3,000 帧（约 120 秒）防爆保护；
  2. 面部特征检测与坐标对齐，生成唇形映射模型 `coords.pkl`；
  3. 时间连续性滑动窗口盒子滤波，消除面部微小抖动；
  4. 伴音分离输出标准 16kHz WAV 单声道音轨（用于音视频时间线对齐与环境噪声基准）；
  5. 资产持久化归档至 SQLite，支持任务进度轮询（0%~100%）、取消与一键设为主播开播形象。
- **1:1 原片生成原则**：坚决不使用任何第三方换脸（Face-Swap）技术，必须使用主播本人出镜闭口视频，从源头杜绝双重嘴唇叠影、嘴唇抽搐与肖像权侵权风险。

### 2. 电商 SKU 预渲染切片工场与混合缝合器 (SKU Slice Pre-renderer & HybridStitcher)
- **SKU 专属切片离线批量工厂 (`ecommerce_sku_slices`)**：
  - **5 大电商动作台词插槽**：针对每个带货商品自动生成/绑定卖点解读 (`intro`)、规格演示 (`specs`)、逼单催付 (`urgency`)、限时抢购 (`stock`)、答疑引导 (`qa`)；
  - **切片响度对齐**：内置 EBU R128 综合响度近似模型（RMS + K 计权 + tanh 软限幅）将切片统一归一化至 `-16 LUFS` 目标响度，并进行 RMS 底噪轮廓匹配，彻底消除切片与实时插话间的音量突变与听觉断层；
  - **端云统一扩散模型批渲染**：端侧与云端统一步调，调度官方 ByteDance LatentSync 扩散模型离线批渲染 MP4 高清切片资产，单切片时长 15~60 秒，画质达 1080P/720P 电影级质感；
   - **保真度如实标注（架构诚实）**：切片落库字段 `render_engine` 记录**实际生效**的渲染引擎。真实云端渲染记为 `latentsync_cloud`；若未配置可达云端 GPU 或缺少主播资产，系统会退化为**主播原始闭口帧镜像循环**（画面真实但**无唇形同步**），此时该字段如实记为 `placeholder_loop`。控制台与开播体检据此显式提示，杜绝把无唇形切片误当作高精带货切片播出。
- **工业级混合缝合器 (`HybridStitcher`)**：
  - **四态确定性状态机**：`PLAYING_BATCH_SLICE`（高清切片轮播中）、`INTERRUPTED_HOLDING`（被弹幕/插话打断并执行平滑停顿）、`STREAMING_REALTIME`（实时神经驱动交互作答中）、`BLENDING_TRANSITION`（4 步平滑过渡回切）；
  - **断点安全回退算法 (`REWIND_SENTENCE`)**：当观众插话打断切片时，系统智能识别当前断点所在句子边界，交互结束后回退至当前句首安全重新起播，绝不出现“半截词、断头句”等严重出戏瑕疵；
  - **切片音频对齐投递与 50ms 交叉淡入**：切片音频自动剥离 WAV 头提取纯 PCM 采样，带代际控制直通系统虚拟音频总线，配合 50ms 交叉淡入淡出（Crossfade）实现无缝听觉衔接；
  - **音频防查双重防线**：每轮切片循环自动重新随机抽取 `uniform(0.985, 1.015)` 动态时域拉伸微变速，粉碎平台音频指纹比对；切片切换交界处动态合成注入“好嘞/那么接下来”等自然过场语气词 TTS，打破机械循环感。

### 3. 5 大电商带货动作状态机 (Action State Machine)
- **标准电商动作槽位**：
  - `0`: 标准待机微呼吸循环 (Idle Loop)
  - `1`: 热情挥手打招呼 (新观众进场欢迎)
  - `2`: 引导点赞求关注 (点赞互动提升权重)
  - `3`: 促单指引下方购物车 (秒杀逼单转化黄金动作)
  - `4`: 双手抱拳 / 鞠躬感谢 (大额礼物打赏触发)
  - `5+`: 商家自定义扩展动作
- **数学镜像往返循环算法 (`mirror_index`)**：采用对称连续索引映射（$0 \to N-1 \to 0$），彻底消除短视频切片首尾衔接时的画面撕裂感与跳帧。
- **双轨研判与优先级抢占**：台词出现“购物车/抢购”或收到大额打赏时毫秒级抢占动作；执行完毕后通过多步 Alpha 混合平滑衰减回待机态。

### 8. 合规风控护栏与反封禁防御体系
- **Aho-Corasick 高性能敏感词过滤**：内置 37 条广告法极限词、医疗承诺、站外导流与竞品攻击规则（通用 17 条 + 抖音 9 条 + 视频号 5 条 + 快手 3 条 + B站 3 条），万级词条匹配耗时仍 < 1ms；支持在控制台按平台/品类批量导入扩展（单次上限 1 万条），覆盖极限词、虚假承诺、竞品攻击、涉政低俗等多品类；

### 9. 多路推流与媒体分发矩阵 (OBS / RTMP / WebRTC / 录制)
- **OBS Virtual Camera**：本地自动注册为 `LiveAgent-VirtualCam` 免驱摄像头，直播伴侣/OBS 直接添加为视频源；
- **RTMP 公网直推**：内置基于 FFmpeg 管道的推流引擎，直接向任意标准 RTMP 服务器推送 720P 竖屏(9:16) H.264+AAC 视频流（与渲染画布同分辨率，宽高/帧率/码率均可配置）；**指数退避断线自愈重连看门狗**（1s→2s→…→15s，默认最多 10 次，`LIVE_AGENT_RTMP_MAX_RECONNECTS` 可配），H.264 profile 显式钉死兼容主流 CDN；
- **原生 WebRTC (WHEP) 极速视窗**：基于 `aiortc` 实现 WHEP 标准端点，支持音画双轨低延迟（200~300ms）在控制台大屏流畅预览；视频轨与渲染输出同分辨率（720×960 竖屏），注入音频按声明采样率自动重采样至 48kHz，杜绝变调；
- **MP4 短视频与讲解切片录制**：控制台一键启停，录制完成自动经 FFmpeg 重编码封装为 H.264+AAC 标准 MP4（默认 720P，支持自定义分辨率与帧率；伴音采样率如实记录）并归档至媒体库，供短视频口播切片二次分发；

### 11. 现代深色控制台与开播真实体检
- **专业暗黑设计规范**：采用翡翠绿（`--accent-emerald`）与琥珀色（`--accent-amber`）专业高质感调色，严格规避廉价蓝紫渐变；
- **开播前硬件与网络环境体检 (Preflight Check)**：由 `GET /api/v1/live/preflight` 返回结构化报告，实测共 **11 项**检查，全部带 `BLOCK / WARN / INFO` 严重级与整改指引：
  1. `ASSET_ONNX_LIPSYNC_MODEL` ONNX 神经唇形权重文件完整性
  2. `ASSET_ANCHOR_SPECIFIED` 正式直播必须指定有效主播资产
  3. `RENDER_ACCELERATION_HARDWARE` 神经渲染硬件加速就绪状态 (CUDA / TensorRT / 云端 Sidecar)
  4. `SPEECH_VOICE_CONFIGURED` TTS 主音色配置与授权校验
  5. `LLM_FACT_SERVICE_READY` 大模型与事实服务链路就绪状态
  6. `STREAM_FFMPEG_BINARY_READY` FFmpeg 音画推流与合流引擎二进制
  7. `SECURITY_PRODUCTION_TOKEN` 生产环境外部访问强制令牌安全策略
  8. `SECURITY_CORS_ORIGIN_WHITELIST` CORS 跨域访问白名单明确性
  9. `SECURITY_ORDER_WEBHOOK_SECRET` 订单 Webhook 生产签名密钥
  10. `COMPLIANCE_AI_DISCLOSURE` 平台 AI 生成合成内容强制显著披露标识
  11. `SKU_SLICE_FIDELITY` 带货切片神经唇形保真度（**存在无唇形同步的占位切片时在正式档位直接阻断开播**）
- **诚实性约定**：正式商业直播档位下任一 `BLOCK` 项失败即拒绝开播并给出整改指引；`SKU_SLICE_FIDELITY` 专门拦截「未配置云端 GPU 时以主播原始闭口帧冒充高精带货切片」的降级产物，确保「绝不静默降级」在商品侧同样成立。
- **另一条独立路径**：`GET /api/v1/live/status` 使用的是早期 `_legacy_preflight_check` 轻量检查，与上述 11 项门禁**不是同一套判定**，请以 `/api/v1/live/preflight` 为开播准入依据。

## 七、快速上手与启动方式

### 1. 环境准备基线
- **操作系统**：Windows 10 / 11 64位（也支持 Linux / macOS 运行核心服务）
- **Python 环境**：CPython 3.12 或 3.13（64位）
- **Node.js 环境**：Node.js 20+ / 22+（仅桌面端 Electron 打包与开发需要）
- **可选依赖**：系统 PATH 中配置 `ffmpeg`（音视频录制与伴音分轨所需）

安装依赖包：
```powershell
# 核心运行时依赖
python -m pip install -r requirements.txt

# 测试与开发依赖
python -m pip install -r server/requirements-test.txt

# 可选 WebRTC 与多媒体高级能力
python -m pip install -r server/requirements-optional.txt
```

---

### 2. 方式一：一键脚本启动 (推荐)

在项目根目录下双击运行：
```powershell
run_agent.bat
```
**自动执行流程**：自动嗅探本机 Python（虚拟环境/系统PATH/安装路径） $\to$ 执行商用全景软硬件体检 $\to$ 自动回收旧端口占用 $\to$ 启动后端服务 $\to$ **自动在默认浏览器中呼起控制台大屏**。

### 3. 方式二：Electron 桌面客户端启动

本系统提供商业交付形态的 Electron 桌面客户端（支持可选内嵌绿色版便携 Python，终端用户免配环境）：

```powershell
# 安装桌面端依赖 (仅首次运行需要)
npm.cmd ci --prefix apps/desktop-ui

# 启动桌面端应用程序
npm.cmd start --prefix apps/desktop-ui
```
Electron 客户端会自动自检后台服务并挂载至 `userData` 独立数据目录，安全隔离。

---

### 4. 方式三：智能启动器命令行启动

使用内置商用智能启动器 `launcher.py`，支持环境自检、国内镜像自动补全缺失依赖、端口占用清理等：

```powershell
# 指定数据存储目录并启动
$env:LIVE_AGENT_DATA_DIR = "G:\ai-live-agent-data"
python launcher.py
```

**常用参数说明**：
- `--no-browser`：启动成功后不自动弹窗呼起浏览器；
- `--check-only`：仅执行系统与硬件健康体检，不启动服务；
- `--auto-install`：若检测到缺少依赖，自动从国内镜像源静默安装；
- `--restart` / `--force`：强制杀死残留占用旧端口的孤儿进程。

跳过启动器交互，直接常驻运行 Uvicorn 服务：

python -m uvicorn server.app:app --host 127.0.0.1 --port 18080

  - `/api/v1/settings/ping` 对 Edge-TTS 执行**真实合成探测**并缓存结论，不再硬编码 `success=True`；微软免费端点返回 403 等上游策略变更会被如实上报为失败而非放行；
  - SKU 切片落库 `render_engine` 记录**实际生效**引擎（`latentsync_cloud` / `placeholder_loop`），开播体检 `SKU_SLICE_FIDELITY` 对占位切片在正式档位直接阻断；
- **高可用看门狗机制**：具备显存超限自动释放（`VRAMWatchdog`）、网络断线熔断器自愈恢复、长音频超时看门狗与媒体管线平滑兜底。媒体质量看门狗（`MediaQualityWatchdog`）已接入帧发布总线 / 音画同步 / 大模型首字 / RTMP 重连四条真实数据源，其有效帧率、丢帧率、漂移 P95、LLM 首字 P95 与 RTMP 重连计数均经 `/metrics` 暴露供 Prometheus 告警，黑屏与画面冻结抽检会触发降级回调（同一异常段只广播一次，画面恢复后闩锁重新武装，第二次异常仍会触发）。帧抽检只在有帧发布时运行，因此**断流/卡死由独立计时器判定**：超过门限未收到任何新帧即触发 `FRAME_STALL` 降级并映射 `Runbook-M07`，计时器线程触发的回调统一派发回事件循环，避免 `asyncio` 事件丢失；帧龄与门限同时经 `/metrics` 暴露。判定受两道前置条件约束：**门限按运行档位分级**（`PRODUCTION`/`PILOT` 2.0s、`PREVIEW` 6.0s、`DEMO` 关闭、未识别档位按最严 2.0s 处理），且**只有推流输出真正就绪时才判定**（RTMP 直推 / 虚拟摄像头 / WebRTC 会话 / 切片录制任一活动，由 `_stream_output_ready_probe` 实时探针判定；无外部观众时不做无意义的降级，输出就绪瞬间重新起算帧龄以避免开播竞态误判）。

### 0.1 鉴权强度说明（历史缺陷已修正）

此前 HTTP 中间件只在「已配置令牌」或「开启 `ENFORCE_REMOTE_AUTH`」时拦截，
**缺少 `LIVE_AGENT_MODE` 判断**，而 WebSocket 守卫一直具备该判断。后果是：

```
绑定 0.0.0.0 + 未配置 API_AUTH_TOKEN + 未开 ENFORCE_REMOTE_AUTH
    → WebSocket 端点被 1008 拒绝（安全）
    → 整个 REST API 完全裸奔（不安全，含凭据配置与开播控制）
```

HTTP 反而成了比 WebSocket 更弱的入口。现已将判定收敛到单一事实来源
[`server/core/security/auth_policy.py`](server/core/security/auth_policy.py)，
两个入口共用 `evaluate_access()`，从结构上消除再次漂移的可能。

### 0.2 零画面直播的 fail-closed 保证

`MediaDriverRouter` 在缺少 `numpy` / `opencv` 时会落到无画面输出的仿真驱动。
历史上 `start()` 不校验驱动类型，任何绕过 `select_driver()` 的路径都会
**静默开出一场「有声音、零画面」的直播** —— 后台不报错、前端不告警、
观众只看到静止画面，属最难被发现的一类事故。

现已在 `start()` 硬拦截：仿真驱动永远无法进入运行态。
商业档位（`PILOT` / `PRODUCTION`）下，神经渲染 Provider 调度失败或异常
同样触发 `MEDIA_DEGRADED` 硬阻断，**绝不用程序化画面冒充真实神经渲染**。

### 1. 数据安全性规范
- **数据 100% 私有化**：直播间所有数据（商品库、交易流水、知识库文档、主播切片、审计日志）均保存在本地单文件 SQLite 数据库中，绝不出网；

## 十一、实操上线与无人值守带货运营指南 (SOP)

为保障在真实商业公网直播（抖音大促、快手 24 小时无人值守、微信视频号、淘宝直播）中达成**“画面高清流畅、口型精准、动作生动灵动、转化率高且抗封禁”**的最佳效果，建议严格遵循以下标准化作业程序（SOP）：

### 1. 形象素材拍摄黄金法则 (到底说话还是不说话？权威解答)

> ⚠️ **【核心结论】制作数字人视频原片：必须全程自然闭口、绝对不说话、不张嘴！声音克隆则单独录制纯音频，声画严格解耦！**

#### 🎥 视觉资产：数字人原片与动作切片（必须全程闭口不说话）
- **为什么绝对不要张嘴说话？（底层神经唇形重绘原理）**：
  - 本系统以**进程内 LatentSync / Wav2Lip-256 ONNX 原生神经推理**为核心（并可通过 LiveTalking 外部服务或云端 Sidecar 节点承载重负载渲染），核心机制为**「局部面部下半区实时重绘 (Local Lip Inpainting)」**：重绘结果经 **LAB 色彩对齐（以上半脸为基准）+ 高斯羽化 alpha 融合**贴回原脸，保证唇色与肤色无缝衔接；
  - 原片视频的作用是提供**稳定的身体身形、衣服质感、发丝细节、眼睛眨眼、面部上半部微表情与自然微呼吸**，而**嘴唇区域（ROI）在直播时完全由 AI 根据实时发音音频逐帧动态重绘**；
  - **如果原片人在说话张嘴**：原视频中下巴在上下剧烈晃动、嘴唇张开露齿，AI 在实时驱动新台词口型时，新嘴型与原片张开的嘴型会发生严重的边缘冲突，直接导致**“双重嘴唇叠影、重叠牙齿鬼影、嘴唇抽搐翻车”**！
  - **如果原片全程自然闭口**：基准面部结构极度稳定，AI 无论是渲染“张嘴大笑、闭口音(M/B/P)、圆唇音(O/U)”均能与原生脸部皮肤实现 LAB 色彩对齐 + 高斯羽化的像素级无缝融合，画面逼真自然无瑕疵。
- **视觉原片录制规范**：
  - **姿态与面部**：面带自然亲和微笑，**全程嘴唇自然微闭（严禁开口张嘴说话）**，双眼自然平视镜头，身体与胸口保持轻微自然的呼吸律动；
  - **时长规格**：录制 **30秒 ~ 1分钟**（最长不超过 2 分钟）的高清 MP4/MOV 视频（推荐手机后置或微单 1080P/4K 60FPS 恒定帧率）；
  - **景别与打光**：胸部以上入镜（半身人像），正面光线均匀柔和（建议使用环形补光灯或双侧柔光箱），避免背光、强阴影或“阴阳脸”；
  - **绿幕与实景**：纯色实景或平整绿幕布（人距幕布 1.5 米防溢绿光），双手自然交叠放于桌前或腹部，避免手部遮挡脸部；
  - **动作切片录制**：挥手欢迎、点赞求关注、指引购物车、鞠躬致谢等带货手势切片，**也同样必须全程闭口不说话**，仅做身体和手势动作。

#### 🎙️ 音频资产：主播声音克隆（独立录制纯音频干声）
- **声音与视频彻底解耦**：声音克隆（CosyVoice、ElevenLabs 等）是**纯音频声纹提取任务**，切勿混在数字人视频里录制；
- **录音规范**：使用手机录音机或高品质电脑麦克风，在安静无杂音无回音的室内，清晰朗读任意一段 **10 ~ 20 秒**的流畅文本；
- **上传入库**：保存为清晰的 WAV 或 MP3 音频文件，直接前往控制台【声音管理】页面上传进行 10 秒人声克隆入库，生成专属 Voice-ID；
- **合流开播**：开播时，系统自动将您克隆的专属声音（TTS）与闭口数字人视频（Avatar）流式合并，实时驱动出真人级唇形对齐与生动直播！

### 2. 算力节点选择与调度策略 (丰俭由人，物尽其用)
- **方案 A：本地有高性能独显 (RTX 3060 / 4060 / 3090 / 4090)**
  - 在【开播向导】中直接确认“端云混合”或“全本地旗舰模式”；
  - 本地承载 LatentSync / Wav2Lip-256 神经渲染，大模型与 TTS 可走云端 API 或本地 Ollama，单机闭环。
- **方案 B：本地轻薄本 / 核显 / 办公机 (⭐ 推荐绝大部分普通商家)**
  - **花小钱办大事**：强烈推荐花费约 **1~2 元/小时** 在 GPU 算力平台（如 AutoDL、Google Colab Tesla T4、Intern InkStone A100）租用一个带英伟达显卡的云端实例；
  - 云端执行一条引导命令：`python scripts/cloud_sidecar_bootstrap.py --port 8010`；
  - 将生成的 WebSocket 隧道地址填入控制台【系统设置 -> 显卡与渲染设置】；
  - 系统**自动优先调度云端显卡**承担全部神经渲染运算，本地仅运行轻量 CPU 调度，机器清爽不发热，直出 1080P 真人高保真画面。
- **方案 C：仅音频联调模式（显式选择）**
  - 无显卡环境**无法产出真实神经唇形画面**。系统按「架构诚实」原则已彻底移除 CPU 假唇形降级路径（能量模拟口型已被硬性禁用，引擎未就绪时直接拒绝启动并暴露根因）；
  - 可显式切换 Mock 仿真模式进行**音频链路、话术与极速打断的联调验证**，该模式仅提供音频、不产出数字人画面；
  - 如需真实画面，请回到方案 B 配置云端 GPU（约 1~2 元/小时），这是轻薄本/无显卡设备获得真人写实画面的唯一正确路径。

### 3. 24×7 无人值守商业带货实战策略
- **开启 0-Token 节能冷场轮播**：
  - 保持环境变量 `LIVE_AGENT_ECO_MODE=true`；
